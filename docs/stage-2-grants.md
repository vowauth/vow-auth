# Этап 2. Разрешения и сессии

Статус: реализовано 2026-10-25. Чем код отличается от проекта — в конце документа.

## Что меняется

Сейчас сессия — запечатанная цепочка «тенант → субъект → устройство → сессия» со штампами отзыва в хранилище эпох. Будет так:

- **Разрешение (grant)** — запись в базе, узел дерева. Источник правды о доступе — только оно.
- **Сессия аккаунта** — корень дерева на устройстве. Клиент держит непрозрачный токен; в базе — только его SHA-256.
- **Вход в тенант** — дочернее разрешение сессии. Один токен сессии открывает все тенанты, в которые аккаунт вошёл на этом устройстве; тенант называется в запросе.
- **Агент** — дочернее разрешение членства (переживает выход) или входа в тенант (привязан к сессии).

```
Сессия аккаунта acc_1 на устройстве laptop      kind = session, токен vas_…
├── Вход в acme (субъект sub_a)                  kind = tenant
│   └── Агент «search», привязан к сессии        kind = agent, токен vag_…
└── Вход в globex (субъект sub_g)                kind = tenant
Агент «claude-desktop» в acme для sub_a           kind = agent, без родителя-сессии
```

Штампы, цепочки, `EpochStore` и его адаптеры (память, Redis) уходят. Redis остаётся хранилищем лимитов.

## Решения

| # | Решение | Почему |
|---|---|---|
| 1 | Сессия аккаунта и входы в тенанты; `sessions.enter(token, tenant)` впускает в другой тенант без повторного входа, если его политика довольна уже пройденными факторами | Решение «учётная сессия + разрешения по тенантам»; соседние вкладки с разными тенантами не мешают друг другу |
| 2 | Сессия хранит доказательства входа (запечатаны вместе с записью) | Политика тенанта при `enter` видит те же доказательства и их время, что и при входе, и может потребовать свежести |
| 3 | Если тенант просит ещё фактор, `enter` отвечает step-up; второй шаг через `signIn` выдаёт **новую** сессию со всеми доказательствами | Новый токен после step-up (защита от фиксации сессии); старая сессия не усиливается задним числом |
| 4 | Скользящий срок простоя (`sessionTimeToLiveMilliseconds`) и абсолютный предел (`maximumLifeTimeMilliseconds`); срок продлевается не чаще, чем прошла половина окна простоя | NIST SP 800-63B-4 и ASVS 3.3: и простой, и абсолютный предел; не писать в базу на каждый запрос |
| 5 | Отзыв любого уровня — одна запись в базу, которая сразу метит всё поддерево; проверка читает одну запись сессии с её входом (одним запросом), привязанный агент — ещё и свою сессию | Работа при отзыве (редко), а не при проверке (на каждом запросе) |
| 6 | Время — по часам хранилища, как было с эпохами | Часы серверов приложения не важны |
| 7 | Токены с приставкой: `vas_` для сессии, `vag_` для агента, дальше 256 бит | Сессию не принять за агента и наоборот; приставку находят сканеры секретов (как `ghp_` у GitHub) |
| 8 | `agents.delegate` получает тенант: агент действует в тенанте | Сессия теперь общая на аккаунт |
| 9 | Кэша на этом этапе нет | Поиск по первичному ключу в Postgres — доли миллисекунды; кэш добавим, если измерения покажут нужду |
| 10 | `sessions.verify` отдаёт аккаунт; HTTP в режиме cookie больше не отдаёт его браузеру | Бэкенд узнаёт аккаунт из сессии, а JavaScript страницы — нет (отличие 2 этапа 1) |
| 11 | Управление сначала отзывает разрешения, потом меняет запись, потом пишет аудит | Отзыв больше не пишет свой аудит в середине операции; при упавшем аудите изменение уже сделано (отличие 1 этапа 1) |

## Схема Postgres

```sql
create table if not exists vow_auth_grants (
	id text primary key,
	kind text not null check (kind in ('session', 'tenant', 'agent')),
	token_hash text unique,
	account_id text not null,
	tenant text,
	subject_id text,
	device text,
	agent text,
	parent_id text references vow_auth_grants (id) on delete cascade,
	session_id text references vow_auth_grants (id) on delete cascade,
	proofs text,
	authenticated_at_milliseconds bigint not null,
	created_at_milliseconds bigint not null,
	expires_at_milliseconds bigint not null,
	idle_expires_at_milliseconds bigint,
	revoked_at_milliseconds bigint,
	seal text not null
);
-- вход в тенант уникален для пары «сессия + тенант»
create unique index … on vow_auth_grants (session_id, tenant) where kind = 'tenant';
-- для отзыва: по аккаунту, по субъекту в тенанте, по устройству, по агенту в тенанте
```

## Порт хранилища

```ts
type GrantKind = "session" | "tenant" | "agent";

type StoredGrant = {
	readonly id: string;
	readonly kind: GrantKind;
	readonly tokenHash: string | undefined;     // у сессии и агента
	readonly accountId: string;
	readonly tenant: string | undefined;        // у входа и агента
	readonly subjectId: string | undefined;     // у входа и агента
	readonly device: string | undefined;        // у сессии и всего, что к ней привязано
	readonly agent: string | undefined;
	readonly parentId: string | undefined;
	readonly sessionId: string | undefined;     // корень-сессия, если есть
	readonly proofs: string | undefined;        // у сессии
	readonly authenticatedAtMilliseconds: number;
	readonly expiresAtMilliseconds: number;     // абсолютный предел
	readonly idleExpiresAtMilliseconds: number | undefined;
	readonly revoked: boolean;                  // не запечатано: только отнимает доступ
	readonly seal: string;
};

type GrantStore = {
	now(): Promise<number>;
	createSession(session: StoredGrant, entry: StoredGrant): Promise<void>;
	createGrant(grant: StoredGrant): Promise<"created" | "conflict">;
	/** Сессия по хэшу токена и, если назван тенант, её вход в него, одним запросом. */
	findSession(tokenHash: string, tenant: string | undefined): Promise<SessionReading | undefined>;
	/** Агент по хэшу токена и, если он привязан, его сессия, одним запросом. */
	findAgent(tokenHash: string): Promise<AgentReading | undefined>;
	extendSession(id: string, idleExpiresAtMilliseconds: number): Promise<void>;
	revoke(level: RevocationLevel): Promise<number>;
};
```

Подписи чтений: `SessionReading = { session, entry, now }`, `AgentReading = { agent, session, now }`.

## Отзыв

| Уровень | Что отзывается |
|---|---|
| `session` | сессия, все её входы в тенанты и привязанные к ней агенты |
| `device` | все сессии устройства с их поддеревьями |
| `account` | все сессии аккаунта с поддеревьями («выйти везде»); агенты с самостоятельным согласием живут |
| `subject` в тенанте | входы субъекта в тенант и все его агенты в тенанте (приостановка и исключение членства) |
| `tenant` | всё в тенанте (отключение тенанта) |
| `agent` в тенанте | все разрешения этого агента в тенанте |
| `delegation` | одно разрешение агента |

Удаление аккаунта удаляет его разрешения вместе с ним.

## Что печать не закрывает

- Снять отметку отзыва или продлить простой в базе напрямую может тот, у кого есть запись в базу; вернуть так доступ можно только к уже выданному токену и не дальше абсолютного предела, который запечатан.
- Удаление строк — отказ в обслуживании.

## Свойства для тестов

1. Токен сессии в базе только хэшем; сессия, вставленная в базу в обход движка (известный хэш, чужая печать), не проходит.
2. Вход выдаёт новый токен; step-up — тоже.
3. Одна сессия открывает тенанты, в которые вошла; в чужой тенант без `enter` — отказ.
4. `enter` впускает без повторного входа, спрашивает политики тенанта, при step-up выдаёт новую сессию.
5. Простой и абсолютный предел; продление не чаще половины окна.
6. Каждый уровень отзыва убивает ровно своё поддерево.
7. Приостановка, исключение, отключение тенанта, удаление аккаунта отзывают нужное; при упавшем аудите изменение сделано.
8. Агент: токен агента не сессия и наоборот; привязанный умирает с сессией; самостоятельный переживает выход.
9. Время по часам хранилища.
10. Контракт хранилища — один для памяти и Postgres.

## Чем код отличается от проекта

- У таблицы разрешений нет внешних ключей на аккаунты, тенанты и субъекты: разрешения можно держать в другом хранилище. Поэтому в порте есть `forget(accountId)`, и удаление аккаунта стирает его разрешения явно — в сессии лежат доказательства входа, а в них почта.
- Добавлен `sessions.end(token, "session" | "device" | "account")` — выход по своему токену, без знания тенанта. HTTP выходит через него, а в режиме cookie новый вход заканчивает сессию, которая была у браузера.
- В HTTP новый маршрут `POST /enter`. `GET /session` в режиме cookie не отдаёт аккаунт; в Bearer-режиме отдаёт.
- Если при управлении упал аудит, разрешения уже отозваны и запись уже изменена: отличие 1 этапа 1 закрыто, тест «changes that take access away are recorded after they are made…».
- Кэша нет (решение 9).
